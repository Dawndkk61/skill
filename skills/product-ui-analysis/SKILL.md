# 产品界面分析

建立可追溯的「页面 → 主题 / 状态 → 组件 → 设计变量」分析。沿用用户选择的产品、已有报告和已确认事实，不重新扩大范围。

## 开始与分析

- 新分析以单个显示器未裁剪、未缩放的全屏原图为输入。提示词已声明使用全屏原图时直接沿用。窗口截图、局部裁切、单独的组件截图和拼接图请换为全屏原图。混合批次先处理符合条件的截图，并说明哪些素材需要替换。整页报告可从已接受的全屏原图裁取组件作为证据。
- 首次分析一个截图批次时，确认截图所用屏幕的系统逻辑工作区尺寸（宽 × 高，Mac 上填写「看起来像」的尺寸）。缺少尺寸时集中询问一次，用户确认不清楚时用原图像素继续。沿用已确认的同一显示条件，换屏或系统显示比例变化时分别记录。
- 从文件读取截图实际像素尺寸。物理分辨率只有在确认为系统逻辑工作区尺寸时才用于标定。相同宽高比本身不足以证明截图覆盖了同一逻辑工作区。
- 按截图实际内容识别产品、页面、主题和状态。多产品可用子目录辅助识别。工作台与 IDE 仅在素材或任务明确区分时分别报告，产品分类无需用户填写。详见[分类分析](references/surface-analysis.md)。
- 用户提供截图时以截图为证据，只有需要且已获授权时才操作真实应用。没有操作记录的截图不写成 Accessibility / DOM 实测或已验证交互。
- 记录原文件、尺寸、哈希、页面、主题、可见状态。保留原图，处理副本记录色彩空间转换，裁切使用原图坐标。取样可用 `scripts/sample_png.py`，支持范围见其 `--help`。
- 每条结论区分观察事实、像素取样、几何估算、配置明示、设计推断、未知。仅在用户确认截图工作区标准且源图可等比映射时换算几何和误差。已确认使用 **2560×1440** 标准的批次中，完整 5120×2880 图按 2× 换算，30 image-px ±5 得到 15 标准 px ±2.5。保留原值、原图坐标和采样区域。设置中直接显示的字号沿用配置值。映射不足时保留图像像素。
- 仅从应用外壳取设计证据。代码编辑器里生成的网页 CSS、终端内容、嵌入网页不是宿主产品变量。截图不能证明源码 token 绑定、实际字体加载、精确字重或未出现的运行状态。
- 分析颜色、圆角、间距、描边、文字 / 字体、字重、字号，缺证据则保留未知。颜色从平坦区域取样，记录区域众数；文字抗锯齿和细边界只作候选。同值不等于同语义，行中心节奏不等于空白间距。详见 [证据规则](references/evidence-rules.md)。

## 数据与报告

按 [数据格式](references/manifest.md) 维护分析 JSON。先用最少代表样本跑通，再增量加入页面；没有可见证据就不补画状态。

默认报告结构如下，当前用户的具体要求优先：

- 跨页变量首页从标题和简短简介直接进入各类变量表。不要额外添加“设计线索”“主题与状态覆盖”等汇总区、方法说明卡或限制说明大块；相关事实、状态与限制写在对应页面、组件和变量的证据中。已有截图单位说明可保留为简短提示。新产品和增量更新沿用这一结构；只有用户明确要求增加总览汇总时才调整。
- 左侧导航按页面分类，提供跨页变量入口。页面原图随主题切换显示一张，主题取值在表格中对照；不生成额外的 Dark / Light 并排全图展示区。
- 侧栏顶部在产品名左侧展示清晰的产品 Logo 图形标记，保持比例、原色并垂直对齐。优先使用用户提供的标志，或从已提供截图中直接裁切，记录来源与坐标；浅色报告优先使用适配浅底的版本。无法取得可靠素材时仅保留文字名称，不用生成、重绘或通用图标冒充。通过 `brand.logo` 提供素材，生成器会内嵌到 HTML；使用方式见数据格式。截图裁切带浅色底时可用 `blendMode: darken` 融合，透明素材保持 `normal`，不对整个报告施加滤镜。
- 每类变量用「原始层 / 语义层 / 组件层」三个**分类级 Tab** 切换整表，默认原始层。命名与映射标为建议；若分层无益，仅保留原始层。
- 直接显示原始值，颜色展示真实色块，数值只在相同单位内排序和绘制相对刻度，不补齐未观察色阶。「依据与范围」直接列页面 / 组件链接。
- 表格后不再重复铺设同一批变量详情卡片。独有说明并入行，通用限制只说明一次。变量链接定位到语义表对应行并自动打开对应 Tab。
- 页面内组件分析完整平铺，展示原图裁切、事实、估算和推断。主题切换不覆盖业务 / 权限状态差异。
- 每张组件分析卡增加“对应设计变量”：按颜色、圆角、间距、描边、文字、字重和字号分组，直接显示当前主题的色块或取值、标准单位/误差、建议别名和依据类型；点击变量名称定位到语义层记录。宽屏使用截图、分析、变量三栏，窄屏将变量区移到下方，不增加展开交互。仅按 `applications` 的页面 ID 与组件 ID 匹配，不能把同名组件或全局变量自动继承进来；未知值、缺少当前主题和没有对应关系分别明确标示。
- 默认分析画布为黑白灰；产品截图和证据色块保留原色，不能对整份报告施加灰度滤镜。按当前用户要求调整报告风格。

使用内置离线生成器：

```bash
python3 scripts/build_report.py /absolute/path/analysis.json --output /absolute/path/report.html
python3 scripts/validate_analysis.py /absolute/path/analysis.json --report /absolute/path/report.html
```

工具仅依赖 Python 标准库。PNG 读取器支持 8 位非交错 PNG；其他格式可用环境中已有工具生成已记录的分析副本。`assets/report.html` 为可改模板，生成器不负责从截图自动识别设计含义。

更新旧版自包含报告的组件变量展示，可先执行下列命令，再校验最终 HTML。此操作保留原有分析数据及图片：

```bash
python3 scripts/component_variables.py report.html --output report.html
python3 scripts/validate_analysis.py analysis.json --report report.html
```

先在分析 JSON 中记录用户确认的标准，再用该批次的宽高运行标定。例如：

```bash
python3 scripts/calibrate_analysis.py analysis.json --width 2560 --height 1440 --output analysis.json --report report.html --report-output report.html
```

首次生成时省略 `--report` 与 `--report-output`，再执行构建器。派生值写入 `standard` / `standardBounds`，原始 `value` / `bounds` 不改写，重复执行不会再次除以 2。仅维护已标定的历史报告时，可对 Devin 首页 5120×2820 这类已核实全宽但高度不足的旧截图使用 `--allow-full-width-partial-height`：按 2× 得到 2560×1410，不拉伸到 1440；坐标仍相对于截图自身。详细格式见数据格式中的“截图工作区标定”。

## 交付前

- 检查引用、尺寸、裁切、取样坐标及变量到组件的关系。表格值必须与分析 JSON 一致。
- 交付前执行报告校验，确认首页简介之后直接进入变量表，没有重新插入已删除的汇总区；定制生成或后处理之后也要校验最终 HTML。
- 有渲染能力时实际检查 Logo 的比例/对齐及页面切换后的加载、分类 Tab、主题、变量定位、组件定位、返回、原图查看、窄屏和控制台错误。只做静态检查时明确说明范围。
- 核对每个组件变量区的条数、取值和链接都来自该组件的对应关系；切换主题要更新变量值，点击变量后能跳到语义记录并返回组件。组件变量区的属性和事件作用域不要与主题按钮、分类 Tab 冲突。
- HTML 自包含图片、数据、脚本，采用同文档导航，不跳去另一个 HTML 源码文件。预览遵循环境访问策略，不把源码编辑器当网页实测；交付说明使用浏览器打开或刷新。
- 输出报告、分析 JSON、简短验证结论，需要便携包时再打包。用户截图、账户信息、研究输出不夹带到可复用 Skill 中。

用于 TRAE、Qoder 等其他产品时复用证据结构，按新截图定义页面 / 组件 / 状态，不继承 Devin 的数值、名称或账号限制。
